From PRD §1.5. **Domain is IT Operations/ITSM — not Life Sciences/Healthcare. No PHI. Do not add
HIPAA-flavoured language; a juror will spot padding.** Privacy is nonetheless a core requirement on
a DPDP (India) + secrets-leakage basis.

## Why privacy is core here (PRD §1.5, do not soften or drop)
1. Ticket data carries personal data of identifiable employees (names, emails, phone numbers,
   employee IDs, manager names) — under India's DPDP Act 2023 + DPDP Rules (Nov 2025), sending this
   text to a model is a purpose the requester didn't contemplate. Redact before it crosses a model boundary.
2. Operational data carries secrets (hostnames, internal IPs, connection strings, bearer tokens, API
   keys, service-account names) — a prompt containing a live credential is an incident, not a nicety.
3. Voice/image intake widen the exposure surface — a voice note may name a colleague, a screenshot
   may show a whole terminal session or a token in a URL bar. **Both paths transcribe/extract first,
   then scrub, then pass downstream** — scrubber sits after the modality converter, never before it.
   Raw audio/images held in memory for the run only, never persisted.
4. Automated action against production requires attributable authorisation — "which agent changed
   this CI, on whose approval, citing what evidence" decides whether this is allowed near production at all.

## Core requirements (not stretch goals — build all of these)
- **Scrub-before-send** at every model boundary: regex for structured secrets/identifiers + a local
  SLM pass for free-text names, with **reversible tokenisation** (`svc-payments-prd` → `[HOST_7]`,
  restored for display to the authorised human, never to the model).
- **Immutable audit trail** — append-only: actor (human or named agent), action, target artifact,
  timestamp, evidence IDs, model used, approval reference, input modality. Viewable in the UI. Table: [schema-db.md](schema-db.md) `audit_log`.
- **Purpose-limited retention** — scrubbed prompts/traces retained; raw payloads, audio, images NOT persisted beyond the run.
- **Local-model routing for the most sensitive step** — raw log excerpts go to a local Ollama SLM, text never leaves the machine. A privacy *architecture* decision, not a cost one.
- **Consent-and-rights posture, stated honestly** — no full DPDP consent-manager flow (out of scope,
  claiming one would be false). Implement data minimisation + purpose limitation + auditability;
  document where a consent/rights layer would attach. Say this out loud in the demo.

## Planted sensitive data for the demo (PRD §6.2 — deterministic, checkable)
- Personal data: names, emails, phone numbers, employee IDs, manager names in tickets/work notes + one voice sample naming a colleague.
- Secrets: connection string with inline password, API key in a config dump, bearer token in a log excerpt, private IPs, internal hostnames + one screenshot with a token visible in a URL bar.
- Adversarial edge case: a log line quoting user input that looks like a prompt injection ("ignore previous instructions") — prove the scrubber + typed-contract boundary contain it.
- Register every planted item in `pii_ground_truth.json` (see [schema-db.md](schema-db.md)) so the eval computes real precision/recall, not an assertion that it works.

## Do not re-decide
Scrub-after-convert ordering, no-persistence-of-raw-media, and "no consent-manager flow, stated
honestly" are resolved. If a phase finds a reason to persist raw audio/images, stop and ask the human.
